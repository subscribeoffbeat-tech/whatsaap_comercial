What we're building (the settled facts)

A self-hosted WhatsApp marketing + support tool for one service company and its customers, talking directly to Meta's Cloud API — no BSP, no per-seat fees, no markup. Single-tenant: one number, one contact database, one team.

In scope (v1)

  • Bulk broadcasts to tagged segments
  • Contacts: tags, custom fields, notes
  • Shared multi-agent inbox (one number)
  • Templates + Meta approval tracking
  • Rule-based automation (keyword/welcome/away)
  • Scheduling + quiet hours
  • Click tracking + saved "clicked" segments
  • Analytics + per-message cost tracking
  • Consent in/out, RBAC, audit log
  • Full Meta-compliance enforcement

Out of scope (decided NO)

  • Catalog + in-app payments (service biz)
  • AI / NLP chatbot
  • Visual drag-drop flow builder
  • AI template generator
  • Click-to-WhatsApp ads manager
  • WhatsApp Flows / native forms
  • Native integrations (Shopify/Zapier…)
  • (one inbound API hook is kept, though)

Every workflow — who, permission, cost

Each flow shows the actor, the permission it needs, the cost, and the rules that bind it.

① Connect WhatsApp & verify business

Adminadmin onlyfree
link number + token→set 6-digit PIN→display-name approval→verify business→webhook verified
Rules: verify on day 1 (else stuck at 250/day); token stored encrypted, never in git; webhook GET-verify must pass.

② Import contacts & record consent

AdminManagermanage contactsfree
upload CSV→map columns→stamp opt-in source + time→apply tags
Rules: only opted-in contacts can ever enter a campaign; opt-in source/time is the consent proof for DPDP.

③ Create & submit a template

AdminManagermanage templatesfree to submit
draft + variables + buttons→submit to Meta→pending badge→webhook flips ✅/❌
Rules: correct category (no promo hidden in "utility"); every variable needs a fallback default or Meta rejects it.

④ Build & send a broadcast

AdminManagersend campaignscosts money
pick segment→approved template→schedule→confirm count→queue → paced worker → Meta
Rules: opted-in only · under 90% of tier cap · respect quiet hours · skip +1 (US) on marketing · max 1 marketing/contact/24h · this is the main cost driver.

⑤ Inbound message arrives

Systemthen Agentfree (service window)
webhook→verify sig + log raw + dedupe→open 24h window→auto-reply or route
Rules: store raw before processing · dedupe by wa_message_id · download media immediately (link expires).

⑥ Agent replies live

AgentManagerAdminchat in inboxfree in 24h
claim/open chat→reply (live)→tag + note→resolve / hand off
Rules: free-form only inside the 24h window; outside it the composer locks to "template only".

⑦ Automation rule fires

Systemconfigured by Admin/Mgrfree if in window
trigger (keyword / new contact / off-hours)→match rule→send reply / route
Rules: v1 = single-step replies only (no branching sequences); STOP keyword always wins.

⑧ Customer opts out (STOP)

Systemautomaticfree
"STOP"→opted_in = false→confirm unsubscribe→excluded forever
Rules: instant & automatic — manual opt-out handling is how you collect blocks & wreck quality.

⑨ View analytics & cost

AdminManagerAgent: own statsfree
delivered / read / failed→cost per campaign & month→quality rating + tier
Rules: each outbound message is stamped with category + cost so spend rolls up automatically.

⑩ Manage team / export or delete data

Adminadmin onlyfree
invite/remove agent→set role→export / delete on request
Rules: every campaign send & setting change is written to the audit log; DPDP delete-on-request honoured.

The hidden costs to watch

A banned number (lost revenue) · over-marketing that triggers blocks · dev/maintenance time · GST · a future AI chatbot (GPU or API).

Because we're a service business, most volume is free service replies + cheap utility — marketing is the small slice. The expensive category barely touches our bill.

Tech, data & APIs (locked)

Two core technologies — Go & PostgreSQL — to keep it simple for an AI-built, lightly-supervised project.

Go + chi
One binary. Web, API, queue worker, websockets. Single-file deploy.
templ + HTMX
Server-rendered UI. No heavy JS framework.
Postgres + sqlc
Data, type-safe. Compiler catches query mistakes.
River
Queue in Postgres. No Redis needed.
WebSocket/SSE
Live inbox & status ticks.
Nginx + certbot
HTTPS on our domain (required for webhooks).

The tool is "ready" when…

Acceptance checklist — tick all and v1 ships.

  • A verified number connects and webhook verification passes
  • Inbound messages appear in the shared inbox within seconds (live)
  • Agent can reply inside the 24h window; composer locks to template-only outside it
  • Contacts import with tags; STOP opts a contact out instantly
  • A template can be created, submitted, and flips to approved/rejected via webhook
  • A campaign sends to a segment, paced under the tier cap, with live delivered/read/failed
  • Non-opted-in contacts are blocked from campaigns; +1 blocked from marketing
  • Quiet hours are respected; frequency cap holds
  • Cost per campaign and per month is shown
  • RBAC matches the matrix; audit log records sends & setting changes
  • Nightly backup runs off-VPS; /health responds; the runbook exists
  • Webhooks dedupe correctly and inbound media is stored before it expires
