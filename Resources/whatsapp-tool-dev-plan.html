The build plan

Tech, APIs, every screen, what each button does, and how the pages link together.

1

The shape of it

One Go program does almost everything: it serves the web pages, runs the background sender, and holds the live chat connections. It only talks to two outside things — Meta and (optionally) the browser.

2

Technology used

Go + chi
Server & router. Handles web pages, the JSON API, and the sender. net/http + chi for clean routes.
templ + HTMX
The pages. Server renders HTML; HTMX swaps bits of the page on click — no heavy JS framework.
PostgreSQL + sqlc
Data. All records; sqlc turns SQL into type-safe Go so the compiler catches mistakes.
River
Queue. Outbound jobs, retries, scheduling — stored inside Postgres, no Redis needed.
WebSocket / SSE
Live inbox. Pushes new messages & status ticks to the dashboard instantly.
Nginx + certbot
Front door & HTTPS. Free auto-renewing TLS on our own domain. Required for Meta webhooks.
Alpine.js
Tiny sprinkles. Dropdowns, modals, toggles — only where HTMX isn't enough.
.env + JWT
Secrets & login. Tokens in env files; our own session/JWT auth (no Auth0).
3

APIs used

A) Meta Cloud API — the only outside one (use current version, v23.x)
POST/{phone_number_id}/messagessend text / template / media
GET/POST/{waba_id}/message_templateslist & submit templates (note: not "whats_app_templates")
POST/{phone_number_id}/mediaupload images / docs → get a media id
GET/POST/whatsapp/webhookour endpoint Meta calls: GET = verify, POST = inbound + statuses

Always verify the webhook signature (X-Hub-Signature-256) and store the raw payload before processing.

B) Our own internal API (what the dashboard calls)
POST/api/auth/login · /logout · /invitesessions & agent invites
CRUD/api/contacts · /tagslist, import, tag, segment
CRUD/api/templatesdraft → submit → track status
CRUD/api/campaignsbuild, schedule, launch, report
GET/api/conversations · /:id/messagesinbox threads
POST/api/conversations/:id/replyagent sends a message
GET/api/analytics/overviewdelivered / read / failed numbers
GET/ws (or /events)live updates to the open dashboard

6

The reusable UI pieces

The shell

Left sidebar nav · top bar (search, number status, profile menu) · toast notifications · loading spinners.

Data table

Used for contacts, campaigns, templates. Search, sort, filter, bulk-select, pagination.

Chat composer

Text box · emoji · attach file · "send template" button · the 24h-window lock state.

Status badges & chips

queued · sent · delivered · read · failed. Tag chips (colored). Approval badges: pending/approved/rejected.

Modals

Confirm send · import CSV · invite agent · new template. Always a clear primary button + cancel.

Forms & wizards

Stepper for the campaign builder; inline validation; disabled buttons until valid.

7

What happens when you click

The important button-by-button behaviour.

Click "Connect WhatsApp" → opens Meta login → on success we store the number + token → onboarding marks "done" → redirect to Dashboard.
Click a sidebar item → HTMX loads that page's main area (no full reload) → the clicked nav item highlights.
Click a conversation → loads the full thread, marks it read → composer is enabled if inside the 24h window, otherwise shows "send a template instead".
Type + hit Send (reply) → message appears instantly (greyed) → POST to our API → we call Meta → ticks update live (sent→delivered→read) via the socket.
New inbound message arrives → webhook fires → we save it → push to the open inbox → unread badge bumps → auto-reply runs if a keyword matches.
Click "New campaign" → Send → wizard (audience→message→schedule→review) → a confirm modal with the recipient count → on confirm, jobs get queued → a live progress bar fills as the worker sends.
Click "Import contacts" → upload CSV → map columns → preview first rows → confirm → contacts saved + tagged → toast "imported 1,204".
Click "Submit template" → form validates → sent to Meta → row shows a pending badge → later a webhook flips it to approved ✅ or rejected ❌.
Click a tag / status filter → table or inbox re-queries and re-renders just the list — instant, no reload.
8

How the pages connect

Login is the gate. First-timers set up WhatsApp; everyone else lands on the Dashboard hub, which reaches every page.
